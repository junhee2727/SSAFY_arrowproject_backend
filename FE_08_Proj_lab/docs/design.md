# Enjoy Trip 디자인 가이드

작성 기준: 2026-10-02 · `06_enjoytrip.html`의 현재 구현

두 사람이 같은 디자인 기준으로 화면을 구현하기 위한 문서입니다. 색상, 폰트, 크기, 간격은 현재 CSS와 지도 클러스터 설정에서 가져왔습니다. 새로운 페이지에서도 아래 변수와 컴포넌트 클래스를 우선 재사용합니다.

## 2. 디자인 방향

- 토스 느낌의 밝은 회색 배경과 선명한 블루를 사용합니다.
- 주요 행동인 **관광지 조회**에 블루 배경을 사용하고, 보조 행동은 연한 블루로 구분합니다.
- 지도·필터·조회 버튼을 하나의 흰색 패널 안에 배치합니다. 내부 구분은 얇은 경계선으로 표현합니다.
- 큰 제목, 충분한 여백, 둥근 모서리로 읽기 쉬운 화면을 만듭니다.
- 제목, 일반 본문, 보조 설명 순서로 글자 크기와 색의 강도를 구분합니다.

## 4. 폰트와 타이포그래피

### 공통 설정

```css
font-family: "Noto Sans KR", -apple-system, BlinkMacSystemFont,
  "Apple SD Gothic Neo", "Malgun Gothic", sans-serif;
font-size: 14px;
line-height: 1.5;
```

현재 HTML에서 Google Fonts의 **Noto Sans KR 400·500·600·700**을 불러옵니다. `400`은 일반 본문, `500`은 라벨·선택값, `600`은 버튼·작은 제목, `700`은 주요 제목에 사용합니다. 아래 표에서 별도 설명이 없는 줄 높이는 `1.5`를 상속합니다.

## 6. 주요 컴포넌트

### 선택 상자 — `.field`

- 높이 **48px**, 모서리 **12px**, 테두리 **1px**입니다.
- 내부 여백은 왼쪽 16px, 오른쪽 36px입니다. 오른쪽 공간은 화살표와 글자가 겹치지 않게 확보합니다.
- 화살표는 18px SVG이며, 오른쪽에서 14px 떨어진 위치에 배치합니다.
- 비활성 여부는 실제 `disabled` 속성으로 표현합니다.

### 조회 버튼 — `.button`

| 구분 | 배경 | 글자 | 최소 높이 | 모서리 |
| --- | --- | --- | --- | --- |
| 주 버튼 / `.button-primary` | `#3182F6` | 흰색, 16px / 600 | 52px | 14px |
| 보조 버튼 / `.button-secondary` | `#E8F3FF` | `#2272EB`, 14px / 600 | 44px | 12px |

두 버튼은 필터 영역 너비 전체를 사용합니다. 아이콘과 문구의 간격은 10px입니다. 541~860px 화면에서는 두 버튼이 가로로 배치되어 보조 버튼도 높이 52px, 모서리 14px을 사용합니다.

### 배지

- `.page-tag`: 기본 너비 143px, 패딩 8px 16px, 모서리 24px입니다.
- `.region-badge`: 기본 최소 너비 194px, 패딩 8px 14px, 아이콘과 문구 간격 8px, 모서리 24px입니다.
- 둘 다 연한 블루 배경과 진한 블루 글자를 사용합니다.
- 지도 왼쪽 위 `.map-result`는 흰색 배경, 최소 높이 40px, 패딩 10px 16px, 모서리 12px입니다. 클릭 기능이 없는 상태 안내입니다.

### 지도 컨트롤

- 버튼 크기는 **40 × 40px**, 아이콘 크기는 20px입니다.
- 확대·축소 버튼을 하나의 모서리 12px 그룹으로 묶고, 모든 장소 보기 버튼은 아래에 12px 간격으로 배치합니다.
- 기본 위치는 지도 위·오른쪽에서 각각 24px입니다. 결과 배지는 위·왼쪽에서 각각 24px입니다.
- 기본 아이콘 색은 `#4E5968`, 호버 배경은 `#E8F3FF`, 호버 아이콘 색은 `#2272EB`입니다.

### 아이콘

현재 HTML의 SVG `<symbol>`을 `<use>`로 재사용합니다. `.icon`은 `fill: none`, `stroke: currentColor`, 선 굵기 1.8, 둥근 선 끝과 모서리를 사용합니다.

| 위치 | 크기 |
| --- | --- |
| 기본 아이콘·주 버튼·지도 컨트롤 | 20px |
| 브랜드 아이콘 | 21px, 선 굵기 2 |
| 보조 버튼 | 18px |
| 지역 배지·지도 아래 안내 | 16px |

새 화면에서 아이콘을 사용할 때는 원본 HTML의 해당 `symbol` 정의도 포함합니다. 장식 아이콘은 `aria-hidden="true"`, 아이콘만 있는 버튼은 기능을 설명하는 `aria-label`을 유지합니다.

| 빈 조회 결과 | 이전 마커·클러스터 제거, `조회된 장소가 없어요` 표시 |
| 조회 실패 | `조회에 실패했어요. 다시 시도해주세요` 표시, 버튼 활성 상태 복구 |

버튼·선택 상자의 전환 시간은 **0.15초**입니다. 스피너는 **0.8초**에 한 바퀴 회전합니다. `prefers-reduced-motion: reduce`에서는 애니메이션·전환 시간을 최소화하는 현재 규칙을 유지합니다.

결과 개수는 화면에 그려진 클러스터 원의 수가 아니라 **유효한 좌표를 가진 전체 마커 수**입니다. 예를 들어 200개와 25개로 묶인 두 클러스터가 있어도 결과 개수는 225곳입니다.

## 8. 마커 클러스터 디자인

클러스터 스타일은 `enjoytrip.css`가 아닌 **`01_api/js/kakao.js`의 `MarkerClusterer.styles`**에 정의되어 있습니다.

| 포함된 마커 수 | 원 크기 | 배경 | 숫자 색 | 줄 높이 |
| --- | --- | --- | --- | --- |
| 2~9개 | 40 × 40px | `#E8F3FF` | `#2272EB` | 34px |
| 10~99개 | 48 × 48px | `#3182F6` | `#FFFFFF` | 42px |
| 100~999개 | 56 × 56px | `#3182F6` | `#FFFFFF` | 50px |
| 1000개 이상 | 64 × 64px | `#3182F6` | `#FFFFFF` | 58px |

공통 규칙은 원형 모서리, 흰색 테두리 3px, 숫자 15px / 700, 가운데 정렬입니다. `box-sizing: border-box`이므로 표의 원 크기에 테두리도 포함됩니다.

- `gridSize: 60`: 화면 픽셀 기준으로 가까운 마커를 묶습니다.
- `averageCenter: true`: 포함된 마커의 평균 위치를 클러스터 중심으로 사용합니다.
- `minLevel: 5`: 지도 레벨 5 이상에서 클러스터링하며, 5 미만으로 확대하면 개별 마커가 표시됩니다.
- 클러스터 클릭 시 SDK의 기본 확대 동작을 사용합니다. 개별 마커에 마우스를 올리면 장소 이름을 확인합니다.

**브랜드 블루를 변경할 때는 CSS 변수와 클러스터의 JS 색상도 함께 수정합니다.** 현재 JS의 색상은 CSS 변수를 자동으로 읽지 않습니다. 개별 마커·지도 타일·장소 인포윈도우의 기본 형태는 카카오 SDK를 사용합니다.

## 9. 반응형 규칙

미디어 쿼리는 **1100px → 860px → 540px** 순서로 적용됩니다. 작은 화면은 앞선 규칙을 상속하고 추가로 덮어씁니다.

| 화면 너비 | 페이지 좌우 여백 | 필터·지도 | 분류 필드 | 조회 버튼 | 지도 최소 높이 |
| --- | --- | --- | --- | --- | --- |
| 1100px 초과 | 최소 40px, 콘텐츠 최대 1248px | 왼쪽 352px 필터 / 오른쪽 지도 | 세로 | 세로 | 592px |
| 861~1100px | 24px | 왼쪽 320px 필터 / 오른쪽 지도 | 세로 | 세로 | 592px |
| 541~860px | 24px | 위 필터 / 아래 지도 | 동일 너비의 가로 3열 | 가로 2열 | 480px |
| 540px 이하 | 16px | 위 필터 / 아래 지도 | 세로 | 세로 | 400px |

540px 이하의 추가 규칙:

- 상단 헤더 높이는 72px, 브랜드 아이콘 박스는 34px, 브랜드 설명은 숨깁니다.
- 패널 모서리는 22px, 패널 헤더 패딩은 20px입니다.
- 패널 제목과 설명은 세로 배치하며 간격은 4px입니다.
- 지역 배지는 최소 너비 제한을 해제합니다.
- 필터 패딩은 세로 22px / 가로 20px입니다.
- 시·도와 시·군·구는 2열을 유지하고 간격만 12px로 줄입니다.
- 분류 필드 사이 간격은 18px입니다.
- 지도 배지·컨트롤의 가장자리 간격은 16px입니다.
- 지도 배지는 글자 12px, 패딩 10px 12px을 사용합니다.
- 안내와 외부 링크는 공간이 부족하면 다음 줄로 이어집니다.

고정 너비 때문에 가로 스크롤이 생기지 않도록 Grid 자식의 `min-width: 0`과 `minmax(0, 1fr)`을 유지합니다.

## 10. 팀원이 컴포넌트를 적용하는 방법

`01_api` 안의 다른 페이지에서 사용할 경우 같은 폰트 로딩과 아래 CSS 링크를 적용합니다. 다른 경로의 페이지라면 상대 경로를 조정합니다.

```html
<link rel="stylesheet" href="./css/enjoytrip.css" />
```

선택 상자는 기존 `.field` 구조를 사용합니다.

```html
<div class="field">
  <label for="selectSido">시·도</label>
  <select id="selectSido" data-type="시도" disabled>
    <option value="" selected disabled>시도 선택</option>
  </select>
</div>
```

버튼은 공통 클래스와 역할 클래스를 함께 사용합니다.

```html
<button class="button button-primary" type="button">관광지 조회</button>
<button class="button button-secondary" type="button">내 주변 관광지 조회</button>
```

새 화면의 기능에 맞게 아이콘과 ID를 추가합니다. 공통 규칙 변경은 `enjoytrip.css`에서 처리하고, 새로운 페이지의 고유 스타일은 별도 클래스 또는 해당 페이지 전용 CSS에 정의합니다. 현재 CSS의 클래스는 페이지별로 자동 격리되지 않으므로 `.field`, `.button`, `.icon` 등을 다른 모양으로 전역 덮어쓰지 않습니다.

## 11. 기존 JS와 연결할 때 유지할 구조

| 역할 | 필수 ID | `data-type` |
| --- | --- | --- |
| 시·도 | `selectSido` | `시도` |
| 시·군·구 | `selectGugun` | `구군` |
| 대분류 | `selectClass1` | `대분류` |
| 중분류 | `selectClass2` | `중분류` |
| 소분류 | `selectClass3` | `소분류` |
| 관광지 조회 버튼 | `btn_trip_search` | — |
| 주변 관광지 조회 버튼 | `btn_around_search` | — |
| 지도 컨테이너 | `map` | — |

`map.js`는 로딩 시 다섯 선택 상자와 두 버튼에 이벤트를 연결하므로, 모듈을 사용하는 페이지에는 이 요소들이 모두 있어야 합니다. ID는 한 문서 안에서 중복되지 않도록 합니다. `label`의 `for`와 선택 상자의 ID도 일치시킵니다.

디자인 상태를 연결할 때는 기존 이벤트를 재사용합니다.

| 이벤트 | 발생 위치 | 데이터 / 화면 용도 |
| --- | --- | --- |
| `enjoytrip:search-state` | `map.js` | `phase`: `loading`·`complete`·`error`, 로딩 중 `loaded`·`total` 제공 |
| `enjoytrip:map-updated` | `kakao.js` | `count`: 지도에 등록한 전체 마커 수 |

현재 페이지의 `map-result-label`, `region-label`, `map-state`, `map-state-message`, `map-controls`, `map-help`는 HTML 안의 초기화 코드가 사용합니다. 지도 컨트롤 ID는 `map-zoom-in`, `map-zoom-out`, `map-fit-markers`입니다. 이 구조를 변경하면 연결 코드도 함께 변경합니다.

## 12. 2인 협업 적용 기준

권장 분담은 한 사람이 **공통 레이아웃·CSS·아이콘**, 다른 사람이 **데이터 조회·지도·상태 연결**을 맡는 방식입니다. 실제 담당자는 팀에서 정하되, 공통 CSS를 두 사람이 동시에 수정할 때는 변경할 컴포넌트를 먼저 공유합니다.

1. 새 화면을 만들기 전에 사용할 색상 변수, 제목 단계, 기존 컴포넌트를 정합니다.
2. 공통 색상·폰트·간격을 바꾸면 CSS와 이 문서를 함께 수정합니다. 클러스터 색상 변경은 JS도 포함합니다.
3. JS가 사용하는 ID와 이벤트는 함께 확인한 뒤 변경합니다.
4. 화면별 임시 스타일을 공통 클래스에 덮어쓰지 않고 해당 화면의 클래스로 구분합니다.
5. 합치기 전에 1440px, 820px, 390px 화면에서 배치·글자 줄바꿈·가로 넘침을 확인합니다. 버튼과 선택 상자의 포커스·비활성 상태도 확인합니다.

새 페이지에서 같은 브랜드와 버튼, 필터, 패널을 사용한다면 이 문서의 값을 먼저 적용하고, 새로운 디자인 규칙이 필요한 부분만 두 사람이 합의하여 확장합니다.
