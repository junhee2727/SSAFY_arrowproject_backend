# EnjoyTrip 백엔드 프로젝트 필수사항 체크리스트

기준 문서: [자바전공_enjoytrip_16_05_백엔드.pdf](./자바전공_enjoytrip_16_05_백엔드.pdf), 총 18페이지. 점검일: 2026-10-30.

필수 기능은 PDF p.7의 우선순위와 p.8~12의 **기본 기능(필수)** 설명을 따른다. 이전 수업 자료의 TODO는 포함하지 않는다. 체크는 현재 코드에서 구현이 확인된 항목을 뜻하며, 미체크는 미구현·최종 확인 필요 항목이다. 구현 여부와 모든 조건의 실제 실행 검증 완료 여부는 구분한다.

F101~F103은 기존 프론트엔드의 지역·관광 분류 선택과 공공 API 조회 코드로 구현되어 있다. 관광정보용 Servlet·DAO를 새로 구현한 것은 아니다. 최종 검증에서 관광지 66건·숙박 88건·음식점 187건·문화관광 213건·공연/행사 38건·쇼핑 217건을 서울 종로구에서, 추천코스 1,068건을 전국에서 실제 조회했다. API 결과 수와 표시 목록 행 수가 일치했다. 서울 지역의 추천코스는 API가 0건을 반환했으며 빈 결과 안내도 확인했다. 지역 코드가 없는 코스는 지역 조건에서 제외될 수 있다. 상세 조건과 콘텐츠 유형은 [최종 검증 결과](./최종_검증_결과.md)를 따른다.

현재 구현 범위는 로그인한 본인의 정보 조회·이름 수정·탈퇴다. PDF의 필수 기능 설명에 관리자 회원 목록이나 이름·이메일 검색을 별도 필수 기능으로 명시하지는 않는다.

### F108. 로그인 관리

출처: p.7, p.12.

- [x] 로그인을 할 수 있다.
- [x] 로그아웃을 할 수 있다.
- [x] 비밀번호 찾기를 할 수 있다.

PDF는 비밀번호 찾기의 구체적인 본인 확인·복구 방식을 지정하지 않는다. 사용자가 선택한 **가입 시 복구코드 발급** 방식으로 구현했다. 로그인 화면에서 이메일·복구코드·새 비밀번호·확인을 입력하면 비밀번호가 변경되고 새 복구코드가 발급된다. 사용한 코드와 기존 로그인 세션은 만료되며, 새 비밀번호로 다시 로그인해야 한다. 복구코드를 잃어버리면 이메일만으로 재설정하는 우회 절차는 제공하지 않는다.

검증: 서비스 테스트 12개, 실제 HTTP 검사 105건, Chrome 가입·복구·재설정·기존 세션 만료·새 비밀번호 로그인과 기존 회원/게시판 회귀를 통과했다. 비밀번호 찾기 화면은 1440/820/390px에서 확인했다. 상세 계약은 [비밀번호 복구 API](./비밀번호_복구_API.md), 실행 안내는 루트 README를 따른다.

이로써 **1. 필수 기능의 구현 체크와 7개 관광 분류의 대표 실조회는 완료**다. 모든 지역·항목의 전수 검증이나 아래 설계·사용성·최종 제출 항목의 완료를 의미하지는 않는다.

## 2. 구현 목표와 설계 절차

출처: p.3의 목표, p.4의 작업 순서, p.6~7의 요구사항 안내. 기능별 필수 분류와 별도로 확인한다.

- [x] Web MVC Architecture를 바탕으로 클래스를 설계한다.
- [x] Servlet을 활용하여 백엔드 웹 서버를 구현한다.
- [ ] PDF의 Servlet/JSP 활용 목표 중 JSP를 활용한다. — 활용 여부 확인 완료: 현재 미사용·미구현
- [x] 지난 관통 프로젝트의 웹 페이지와 백엔드를 연결한다.
- [x] 요구사항을 분석·수정하고, 실제 구현 범위에 맞는 목록으로 정리한다.

- [x] 설계한 클래스를 바탕으로 소스코드를 구현한다.

현재 구조는 Servlet → Service → 메모리 DAO → DTO이며, 화면은 Live Server의 HTML/JavaScript와 Tomcat JSON API로 연결한다. 소스와 빌드된 WAR 모두 JSP·JSPX·JSPF·태그 파일이 0개다. ApiController는 JSON을 반환하고 HomeController는 HTML로 리다이렉트한다. JSP API·JSTL 의존성만 선언되어 있으며 실제 JSP 화면은 구현하지 않았다. 따라서 활용 여부 확인은 완료했지만 JSP 활용 목표는 미체크로 남긴다. PDF에 없는 ‘모든 HTML을 JSP로 전환’ 같은 세부 조건을 이 체크리스트에서 추가하지 않는다.
