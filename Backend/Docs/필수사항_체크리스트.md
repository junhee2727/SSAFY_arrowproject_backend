# EnjoyTrip 백엔드 프로젝트 필수사항 체크리스트

기준 문서: [자바전공_enjoytrip_16_05_백엔드.pdf](./자바전공_enjoytrip_16_05_백엔드.pdf), 총 18페이지. 점검일: 2026-10-30.

필수 기능은 PDF p.7의 우선순위와 p.8~12의 **기본 기능(필수)** 설명을 따른다. 이전 수업 자료의 TODO는 포함하지 않는다. 체크는 현재 코드에서 구현이 확인된 항목을 뜻하며, 미체크는 미구현·최종 확인 필요 항목이다. 구현 여부와 모든 조건의 실제 실행 검증 완료 여부는 구분한다.

F101~F103은 기존 프론트엔드의 지역·관광 분류 선택과 공공 API 조회 코드로 구현되어 있다. 관광정보용 Servlet·DAO를 새로 구현한 것은 아니다. 실제 외부 API 조회는 서울 종로구 역사관광 66곳을 확인했으며, 위 콘텐츠 종류를 모두 개별 실조회한 것은 아니다. 제출 전 각 종류의 조회 결과를 확인한다.

### F108. 로그인 관리

출처: p.7, p.12.

- [x] 로그인을 할 수 있다.
- [x] 로그아웃을 할 수 있다.
- [x] 비밀번호 찾기를 할 수 있다.

PDF는 비밀번호 찾기의 구체적인 본인 확인·복구 방식을 지정하지 않는다. 사용자가 선택한 **가입 시 복구코드 발급** 방식으로 구현했다. 로그인 화면에서 이메일·복구코드·새 비밀번호·확인을 입력하면 비밀번호가 변경되고 새 복구코드가 발급된다. 사용한 코드와 기존 로그인 세션은 만료되며, 새 비밀번호로 다시 로그인해야 한다. 복구코드를 잃어버리면 이메일만으로 재설정하는 우회 절차는 제공하지 않는다.

검증: 서비스 테스트 12개, 실제 HTTP 검사 105건, Chrome 가입·복구·재설정·기존 세션 만료·새 비밀번호 로그인과 기존 회원/게시판 회귀를 통과했다. 비밀번호 찾기 화면은 1440/820/390px에서 확인했다. 상세 계약은 [비밀번호 복구 API](./비밀번호_복구_API.md), 실행 안내는 루트 README를 따른다.

이로써 **1. 필수 기능의 구현 체크는 모두 완료**다. F101~F103의 모든 콘텐츠 종류 개별 실조회 여부는 앞의 검증 범위 설명과 구분한다.

| --- | --- |

| Usecase Diagram | 현재 저장소에서 제출용 다이어그램을 확인하지 못했다. |
| Class Diagram | 이 폴더의 `class-diagram.mmd`, `class-diagram-dto.mmd`, `class-diagram-support.mmd`가 있다. 제출 문서에서 확인할 수 있도록 렌더링·포함 여부를 최종 확인한다. |
| 소스코드 | `Backend/src/`, `Frontend/`에 구현과 테스트 코드가 있다. |
| 실행 캡처 | `Frontend/docs/screenshots/`와 `Backend/.runtime/screenshots/`에 있다. 최신 검증 캡처인 `.runtime`은 Git 제외 대상이므로 제출용 이미지를 선별해 추적되는 경로에 포함해야 한다. |
| 제출 | 현재 원격 저장소는 GitHub다. GitLab 업로드와 반별 제출 방식은 확인되지 않았다. |

PDF는 README 또는 Word·PowerPoint 문서를 활용한 산출물 정리를 안내한다. **README·Word·PowerPoint를 모두 각각 작성해야 한다는 뜻은 아니다.** 소스코드와 실행 화면 캡처는 원문에서 하나의 제출 항목이지만, 누락 확인을 위해 위에서 분리했다.
